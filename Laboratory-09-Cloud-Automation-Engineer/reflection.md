# Mission Reflection

Automation is very important when managing hundreds of cloud servers because it helps engineers complete repetitive tasks quickly and consistently. Instead of manually performing backups or maintenance on every server, automation allows the same process to run automatically. It saves time, reduces human error, and makes cloud operations more efficient.

However, automation also has risks. If a script contains a destructive mistake, such as an incorrect command that deletes important files, the damage could affect many servers at once. For example, a script scheduled to run on 1,000 servers could cause a serious problem if it was not tested properly. This is why scripts should always be reviewed, tested, and monitored before being used in production.

Writing a Bash script was different from creating a Docker Compose YAML file in Laboratory 06. A Bash script contains commands that Linux executes step by step, while Docker Compose uses a YAML configuration file to describe how containers and services should run. Both tools are useful, but Bash scripting focuses more on automating tasks, while Docker Compose focuses on managing container applications.

Looking back at my GitHub portfolio from Laboratory 01 to Laboratory 09, I can see how much my understanding of cloud computing has improved. At first, I was mainly learning basic Linux commands and cloud concepts. As the activities continued, I learned about cloud infrastructure, Docker, object storage, monitoring, security, and automation. These experiences helped me understand how different cloud technologies work together.

The role I enjoyed the most was Cloud Operations Engineer because I learned how to monitor servers, examine application logs, and identify possible problems. I found it interesting to see how engineers maintain the performance and reliability of cloud applications. Overall, this mission helped me become more confident in using Linux and understanding the responsibilities of a cloud engineer.
